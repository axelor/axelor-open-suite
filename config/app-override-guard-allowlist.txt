# Allowlist of the checkAppOverrideGuard task (RM#117723).
#
# One fully qualified class name per line. Everything after a '#' is a comment.
# A class listed here is not reported by the task even though it overrides a class of
# a lower module without calling isApp(...).
#
# Two kinds of entries were expected here:
#
#   1. Justified exceptions: either the override is behaviour-neutral when the app is off, or
#      the overridden code path is unreachable unless the app of the OVERRIDING module is
#      installed. Such an entry is permanent and MUST carry a comment explaining why.
#      "The overridden module and its app are a prerequisite of this module" is NOT a valid
#      justification: it is true of every cross-module override. See CONTRIBUTING.md.
#
#   2. Known debt: overrides that were already there when the check was introduced. All of them
#      were removed by the #117722 sweeps, so this section is now empty; new entries must be
#      justified exceptions.
#
# Adding a NEW class here instead of guarding it requires a justification in the merge request.
